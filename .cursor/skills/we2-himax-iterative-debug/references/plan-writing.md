# Plan 写作指南

在 `plan-routing.md` 决定**写到哪里**，本文档指导**如何写**——保持紧凑、可回溯、不丢关键细节。

---

## 1. 原则（非模板）

- **可定位**：后人（或 Agent）能根据 plan 快速找到「改了什么文件」「关键数值是多少」「根因是什么」。
- **可复现**：验证命令完整、日志路径明确，无需再问「当时怎么跑的」。
- **可压缩**：同类信息合并（表格、列表），避免逐条重复相同结构。
- **可演进**：plan 会变长，定期做**精细化删改**——删重复、留结论、补索引。
- **可接续**：每轮调试后刷新上下文快照，保证下一会话最小读取即可接续。

---

## 2. 高价值内容（必须保留）

| 类型 | 示例 | 作用 |
|------|------|------|
| **文件路径** | `EPII_CM55M_APP_S/app/scenario_app/optical_cam_oflow/io/camera/cam_input.cpp` | 避免重复搜索 |
| **关键数值** | arena 1680KB / 1408KB、槽位 0xB7B000、波特率 921600 | 避免重复调试 |
| **根因结论** | 「量化校准用白噪声导致 8 像素条纹」 | 避免重复踩坑 |
| **验证命令** | 完整 `run_optical_pipeline.sh ...` 一行 | 可一键复现 |
| **日志路径** | `logs/pipeline/pipeline_xxx_20260223_104837.log` | 证据可回溯 |
| **上下文快照** | `logs/context/context_snapshot_latest.md` | 降低下轮会话读取成本 |
| **决策理由** | 「选方案 A 不选 B，因为…」 | 避免重复讨论 |

---

## 3. 低价值内容（可删或压缩）

| 类型 | 处理方式 |
|------|----------|
| 已完成的「下一步」规划 | 删掉，只留最终结论 |
| 逐轮重复的「命令→结果→结论」 | 合并为表格或摘要，保留关键几轮 |
| 多次相同现象描述 | 压缩为「现象 → 根因 → 动作」一条 |
| 冗长的假设列举 | 只留验证过的；未验证的移到「待验证」小节 |
| 全量 UART/base64 | 永不粘贴；只存日志路径 + 关键行 |

---

## 4. 按 plan 类型区分侧重点

### 规划型 plan（如 plan-001~003）

- **背景与目标**：简短，1~2 段。
- **方案对比**：用表格或列表，每条 1~2 行；决策理由单独一句。
- **实施记录**：完成后压缩为「做了什么 + 关键文件/命令 + 验收结论」。
- **不再保留**：详细的「下一步候选」、已执行的实验步骤流水账。

### 调试型 plan（如 plan-006~009）

- **假设**：每条一行，带验证方式。
- **单轮记录**：假设 / 改动 / 命令 / 关键证据 / 结论；多轮时用表格或 R1/R2 编号。
- **根因破案后**：把「排查过程」压缩为「根因 + 修复方案 + 关键文件」；删除已排除的假设细节。
- **当前配置**：单独一小节，列出宏、数值、路径，便于快速查阅。

### 经验清单型 plan（如 plan-005）

- 每条：结论 + 判据 + 标准动作；不展开过程。
- 关键证据：只存日志路径索引，不贴内容。

---

## 5. 精细化删改时的检查清单

做 plan 压缩时，逐条确认：

- [ ] 所有**文件路径**是否保留？
- [ ] 所有**关键数值**（内存、地址、槽位）是否保留？
- [ ] **根因结论**是否保留？
- [ ] 至少一条**完整验证命令**是否保留？
- [ ] **日志路径索引**是否保留（可只列关键几条）？
- [ ] 是否已执行 `bash scripts/build_context_snapshot.sh` 并刷新 `context_snapshot_latest`？
- [ ] 若主调试 plan 变更，`plan/plan-000-context-index.md` 指针是否同步？
- [ ] 是否有**重复段落**可合并？
- [ ] 是否有**已过期的「下一步」**可删除？

---

## 6. 灵活结构建议

不必固定章节名，按实际内容组织。常见有效结构：

- **目标 / 背景**：为什么做这件事
- **结论 / 根因**：先说结果，再展开（倒金字塔）
- **关键路径 / 配置**：文件、宏、数值、命令
- **执行记录**：若多轮，用编号（R1/R2）或表格；少轮可直接叙述
- **索引**：日志路径、证据文件路径

可省略的：冗长的「我们考虑了 A、B、C…」——只保留最终采用的及理由。

---

## 7. 与 plan-routing 的关系

- `plan-routing.md`：写到哪里（最新 plan vs 独立 history）、何时新建 history。
- 本文档：写什么、怎么压缩、什么必须保留。

两者配合：routing 决定**存放位置**，writing 决定**内容形态**。
